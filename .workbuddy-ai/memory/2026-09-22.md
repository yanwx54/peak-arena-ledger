## 收尾：修掉两个会让每日任务失败/毁数据的缺陷

定时任务建好后做验收，跑第二次时**抓到了真问题**，值得记牢：

### 缺陷 1：Cloudflare 验证时序 —— 固定 sleep 必然翻车
- 现象：`list_articles.py` 返回 `TOTAL unique articles: 0`，解析 0 条，`build_output.py` 因空列表崩溃。
- 根因：`cdp.py` 原写死 `time.sleep(12)` 就取 cookie。实测 wxredian 的 Turnstile **需要约 17 秒**才通过
  （2s 时 title='验证访问'，17s 时才变成正常作者页、links=130）。差这 5 秒 → 拿到无效 cookie →
  后续所有请求都返回「验证访问」页。**wxredian 的验证策略是收紧过的**，早期 cookie 能顶一阵子。
- 修复：改为打开作者页后**轮询**（`document.title` 不含「验证」且 `/art?id=` 链接数 > 0），
  上限 150s；落盘后**再用该 cookie 实测请求一次**校验，不通过则退出码 1。

### 缺陷 2：抓取失败会静默清空数据（更危险）
- 现象：枚举得 0 → `list_articles.py`/`extract_jd.py` 把 `articles_list.json`(277篇) 和
  `jd_records.json`(451条) 直接覆盖成 `[]` → 台账被清空。
- 修复：`daily_update.py` 每轮开始前把这两个文件备份到 `data/.backup/`（已 gitignore）；
  枚举或解析结果为 0 时**立即回滚并中止，不产生任何提交**。

### 附带修复
- **xlsx 非确定性**：openpyxl 保存时把 `docProps/core.xml` 的 `dcterms:modified` 写成当前时间，
  zip 条目也各带生成时刻 → 同样数据每次生成字节都不同 → 每日同步会**空提交**。
  在 `build.py` 加 `freeze_xlsx()` 冻结 core.xml 与 zip 条目时间戳，实测三次生成 md5 完全一致。
- 移除 `_probe.py`（一次性调试脚本，硬编码 `C:\tmp` 路径）。

### 踩到的环境坑
- **`git rm` 中途被中断会留下 `.git/index.lock`**，之后所有 git 写操作全部失败
  （`Unable to create index.lock: File exists`）。删掉该锁即可。
- 一次被 SIGTERM 的命令之后，仓库的 `data/` 与 `output/` 目录整个消失（源工作区完好，已全部恢复）。
  结论：**源工作区才是权威副本**，仓库侧异常时从它恢复。
