# 2026-11-03 排查：站点迁服 + 新 IP 对本机静默丢包（此前 4 天误判为 Cloudflare 挑战）

## 用户问题
「https://wxredian.com/author?id=gh_72517d36a4d7&cycle=202610 我现在打不开」

## 根因（一锤定音）
**不是 Cloudflare 拦人，是站点换了服务器，而新 IP 从本机网络被静默丢包。**

| IP | 使用区间（OTX passive DNS） |
|---|---|
| 45.136.15.27 | 2025-07-28 → **2026-10-26 19:56**（我们最后抓成功那天） |
| 207.57.135.129 | **2026-10-29 16:42** 起（HK，AS139659 LUCIDACLOUD，ipinfo: Tung Chung） |

2026-10-30 起所有轮次失败，正是这次迁服造成的。

## 证据链
1. **Chrome 错误页**：探针截图显示 `ERR_CONNECTION_TIMED_OUT`，`location.protocol='chrome-error:'`。
   → Chrome 错误页标题就是主机名，所以看起来像 `title='wxredian.com' links=0`，
   **被误读成"Turnstile 没过"，白等 150s × 6 轮**（10-30 上午 4 次 + 10-30 10:03 两次 + 本日一次）。
2. **TCP 层**：新 IP 443/80/8080/8443 全部 timeout；`ping` 100% 丢包、**无 RST** → 防火墙静默 DROP。
3. **对照实验**：腾讯云香港节点 43.154.175.195 返回 **ConnectionRefused（RST）** → 到香港的路由本身是通的，
   说明只针对这一个 IP。同机 github.com / baidu.com 均 0.0~0.1s 连通 → 不是断网。
4. **DNS**：DoH（dns.google）权威解析同为 207.57.135.129（TTL 60），老 IP 已下线。
5. **站点是活的**：换出口（WebFetch）首页正常，热文流最新 **2026-10-31 23:59**。
6. **挑战只针对内容路径**：`/author`、`/art` → 跳 `/verify?redirect=`；`/`、`/index?page=N`、`/sitemap.xml`(404) 不拦。
   → 非浏览器客户端拿不到正文；但真实 Chrome + 可达网络是可以过的（10-26 就是这么过的）。

## 飞书上传的授权模型（重要）
- `lark-cli` 两种身份：bot（应用身份）与 user（用户身份），默认 `auto`。
- **bot 身份常缺 `drive:file:upload` 这类「应用身份权限」** → 报
  `app_scope_not_applied / code 99991672`，错误里带 `console_url`（开放平台申请页）。
  应用侧 `auth scopes` 里 `userScopes` 含 `drive:file:upload`，但那是**用户授权**列表，不代表 bot 身份可用。
- user 身份 token 过期 → `need_user_authorization` / `token_missing`。
- **解决办法**：`reconnect_plugin` 重新授权飞书 connector（`feishu@workbuddy-connector-plugins-official`），
  会刷新 user 身份 token（refresh_token 有效期约 7 天）。
- 已在 `daily_update.py` 固化：上传先试自动身份，失败再显式 `--as user` 兜底；两条都失败才报错。
- 同时把飞书步骤改为**失败不阻断 Git 提交**——飞书是分发渠道、Git 是数据落盘，前者挂掉不应让后者也丢。
